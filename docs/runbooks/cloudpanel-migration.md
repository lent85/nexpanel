# Runbook: CloudPanel Import & Migration

NexPanel provides a first-class import pipeline for migrating sites from CloudPanel 2.x to NexPanel without manual terminal commands.

## 1. Supported Sources

| Source | Input | Recommended Use Case |
|---|---|---|
| **A — Remote `backup.tar`** | Remote backup tar file generated by CloudPanel rclone backups | Existing remote backup file stored in S3/Wasabi/SFTP |
| **B — Local Pair** | `local-files.tar.gz` + `local-db.sql.gz` | Manual exports from CloudPanel File Manager and DB tab |
| **C — Live CloudPanel SSH** | Host, SSH port, user, private key / one-time password | **Recommended:** Live zero-friction migration directly from CloudPanel server |

## 2. Migration Workflow

```
1. Ingest Source (upload tar, pair, or SSH connection)
2. Detect -> Manifest inspection (domain, PHP, DB, vhost, cron)
3. Mapping Screen -> Choose target PHP, DB engine (MySQL 8.4/MariaDB/Postgres), and domain
4. Dry-Run -> Simulates all planned changes (creates NOTHING)
5. Execute Import -> Files unpacked, DB created, SQL imported, wp-config rewritten, NPM host created
6. Post-Import Verification -> HTTP 200, DB table check, WordPress login check
7. 1-Click Rollback available for 7 days
```

## 3. Hard Rules During Migration

1. **Rule R1:** NPM owns ports 80/443. The proxy host is automatically created with forward_host set to the origin container name on the `proxy` network (never `localhost` or `127.0.0.1`).
2. **Rule R2:** Target database is placed on any registered pluggable database engine (internal or external).
3. **Rule R3:** WordPress on PostgreSQL is blocked by default with a warning. WordPress sites must map to MySQL or MariaDB.

## 4. CLI Migration Example

```bash
# 1. Test via Dry-Run first
nxctl import:cloudpanel --file backup.tar --dry-run

# 2. Run full migration
nxctl import:cloudpanel --file backup.tar --db-engine <engine-id>

# 3. Live SSH migration
nxctl import:cloudpanel --host old.cloudpanel.example --user root --key ~/.ssh/id_ed25519
```

## 5. Zero-Downtime Cutover Flow

1. Complete the import on NexPanel while public DNS still points to CloudPanel.
2. Verify the imported site using temporary domain or `curl -H "Host: example.com" http://<NEW_SERVER_IP>`.
3. Lower DNS TTL to 300 seconds.
4. Update the DNS A record to the new server's IP.
5. NexPanel automatically issues the Let's Encrypt SSL certificate via NPM HTTP-01 challenge.
6. Keep the legacy CloudPanel server running for 7 days as a safety fallback.
